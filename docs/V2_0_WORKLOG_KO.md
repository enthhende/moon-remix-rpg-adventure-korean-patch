# v2.0 작업기

## 목표

v2.0의 목표는 디스크에 남아 있지만 정상 플레이로 볼 수 없었던 자료를
가능한 한 정직하고 안전하게 감상할 수 있게 만드는 것이었습니다. 원작의
위험한 디버그 메뉴를 통째로 노출하거나, 남아 있지 않은 내용을 새 대사로
창작해 완성 이벤트인 것처럼 꾸미지 않는다는 원칙을 세웠습니다.

동시에 실제 플레이 피드백에서 발견한 이름 입력·조사·특수문자 문제와
릴리스 후보 이후의 번역·줄바꿈·글리프·MD 정렬 문제를 모두 같은 최종
이미지에 반영했습니다.

## 깨끗한 원본에서 매번 다시 만들기

후보 이미지는 이전 시험판을 직접 덧칠해 만들지 않았습니다. 지원 원본인
일본판 Rev 1에서 시작해 고정된 v1.1 변환과 v2.0의 선언된 변경을 정해진
순서로 다시 적용했습니다. 이렇게 해야 이전 실험의 우연한 상태나 잘못된
바이트가 다음 후보에 섞이지 않습니다.

최종 exact O46도 서로 분리한 두 작업 경로에서 다시 만들었습니다. 두 BIN,
Expected Writes, 정적 검증 보고서가 모두 바이트 단위로 일치했습니다.

## 안전한 숨겨진 메뉴

첫 단계는 타이틀의 Game Start/Continue 화면에서만 `SELECT`로 들어갈 수
있는 작은 메뉴를 만드는 일이었습니다. 원작 디버그 기능은 저장 데이터와
진행 상태를 건드릴 위험이 있어 분석에만 사용하고, 공개판 실행 경로에서는
제외했습니다.

최종 메뉴에는 보너스 자료관, 용의꼬리 재구성판, 소년과 할머니, 타이틀
복귀만 남겼습니다. 결말 스포일러 경고와 확인 단계를 두고, 숨겨진 모드
중에는 일반 저장을 진행하지 않도록 보호했습니다.

## 16개 자료, 48화면의 보너스 자료관

보너스 자료관은 원본 이미지 16화면과 한국어 해설 32화면으로 구성했습니다.
PS1 해상도와 색상 수에 맞춰 화면을 다시 배치하고 4비트 이미지로
변환했습니다. 영문·따옴표는 비례 전진폭을, 한글은 읽기 쉬운 고정 간격을
사용했습니다.

화면을 넘길 때마다 CD에서 다음 자료를 읽는 구조라 음악 묶음까지 동시에
다루면 로딩과 복귀가 불안정해졌습니다. 여러 실험에서 화면 갱신 정지와
복귀 실패가 반복돼, 안정적으로 동작한 무음 자료관을 최종 사양으로
정했습니다.

## 용의꼬리 재구성

용의꼬리 관련 자료는 완성된 한 이벤트가 그대로 남아 있지 않았습니다.
같은 맵을 여러 시점에 재사용하는 장면과 프로그램 조각을 단순 번호순으로
실행하면 첫 처단 뒤 검은 화면에 멈추거나, 회랑을 반복하거나, 뒤 장면이
너무 일찍 실행됐습니다.

각 장면의 완료 상태와 실제 이벤트 프로그램을 다시 추적해 허용된 전환만
통과시키는 감독 흐름을 만들었습니다. 첫 용사 처단, 탓쿤과의 만남,
상처 입은 이들의 행렬과 치료, 소년과 용의 관계, 로비의 해방을 거쳐
타이틀로 돌아갑니다. 연결과 안전한 복귀 코드는 새로 구현했지만 원작에
남아 있지 않은 결말 대사를 창작하지는 않았습니다.

진행 경계를 벗어나 검은 화면이나 반복에 빠지지 않도록 보호했고, 필요할
때 `START+SELECT`로 타이틀에 복귀하는 비상 입력도 넣었습니다.

## 소년과 할머니

처음에는 집 밖과 집 안이 두 분기처럼 보였지만 실제로는 이어지는 한
이벤트였습니다. 중복 항목으로 만들지 않고 문을 통해 자연스럽게 연결되는
하나의 항목으로 정리했습니다.

불완전한 침대 구석 트리거는 차단하고, 남쪽 출구는 타이틀로 안전하게
돌아가도록 바꿨습니다.

## 이름 입력 피드백

최초 v2.0 후보를 실제 플레이하면서 이름 입력기 주변의 세 문제가
드러났습니다.

- 이름 입력 화면의 `♥`가 일부 일반 대화에서 `♠`로 바뀜
- 이름의 `@`가 일부 일반 대화에서 별 모양 문자로 바뀜
- 이름 끝에 특수문자가 있으면 조사·호격이 마지막 한글을 보지 못함

`♥`와 `@`는 일반 대화 변환표의 해당 항목을 입력기와 같은 문자로
연결했습니다. 조사·호격은 이름의 마지막 칸만 보는 대신 7칸 안에서
뒤에서부터 마지막 한글 음절을 찾도록 바꿨습니다. 이 스캐너는 주인공
이름에만 적용했고 아이템명 판별기와 기존 아이템 결과는 건드리지
않았습니다.

일반 대화와 달의 여왕 장면에서 `게임구러기@♥`, `게임구러기@♥야`,
`게임구러기@♥여...`를 확인했습니다. 함께 발견한 데이터 삭제 질문
겹침은 `이 데이터를 삭제하시겠습니까?`로 줄였고, 무츠지로의 호칭은
`〔이름〕씨~ / 기다리고 있었어요~`로 확정했습니다.

## 번역 검수와 긴 이름 줄바꿈

최초 런타임 후보 뒤에도 승인된 번역과 줄바꿈을 단계적으로 반영했습니다.
누적 TSV를 통째로 다시 들여오지 않고 안정 ID와 물리 슬롯으로 새 승인만
선별했습니다. 검수 도구에는 실제 15코드 자동 줄바꿈 규칙으로 일반 대사
3행 초과만 모아 보는 필터를 추가했고, 이미 반영한 승인이 다음 TSV에
다시 나오지 않도록 마이그레이션했습니다.

후반에는 최대 7자 이름을 넣었을 때 엔딩 대사가 잘릴 수 있는 페이지를
집중적으로 다시 나눴습니다. exact O46의 대상은 모두 3행 이하,
행당 15코드 이하이며, raw 01799는 이름 `민지`로 세 행 전체와 다음
대화 진행을 PS1에서 직접 확인했습니다. 긴 이름은 같은 문구를 쓴 Switch판
런타임과 PS1 파서 정적 계산을 결합해 확인했으며, 이를 PS1 긴 이름
런타임이라고 과장해 기록하지 않았습니다.

마지막 국소 교정에는 세계 지도 지명 `타마야 공방`, `어이, 우타코!`,
여러 엔딩 줄바꿈과 raw 01799 문구가 포함됩니다.

## 영문·특수문자와 MD 정렬

영문·숫자·특수문자는 후보 시트와 실제 게임 화면을 함께 보며
전수했습니다. 숫자는 기존 16px 경로를 유지했습니다. 소문자와 여러
특수문자는 Galmuri 계열로 정리하되 쉼표와 가운데점·2점·3점 계열은 기존
모양을 남겼습니다.

대문자는 한글과 세로 높이를 맞추면서 오른쪽 한 열을 여백으로 둔
Galmuri14 safe7-in-8을 적용해 이웃 글자가 붙어 보이지 않게 했습니다.

MD 선택 화면과 번의 곡 설명은 글자 수가 아니라 실제 4/8/16px 전진폭으로
문장 전체의 시작점을 계산하도록 바꿨습니다. 첫 구현에서는 가운데 정렬은
맞았지만 일부 행의 자간이 내용에 따라 흔들리는 회귀가 생겼습니다. 서로
다른 호출 규약을 같은 것으로 취급한 것이 원인이었고, 원래의 평면 인덱스
입력을 복구한 뒤 최종 런타임에서 MD 전체의 자간과 문장 가운데 정렬을
정상으로 확인했습니다.

## 최종 검증과 동결

exact O46의 BIN SHA-256은 다음과 같습니다.

```text
c5e58d0b9030a0f8683126f2866b633c70e6ea5e12c699524dfece1c67fcc43d
```

최종 단계에서 다음을 확인했습니다.

- 독립 이미지 재빌드 2회가 exact O46으로 바이트 일치
- 독립 xdelta 생성 2회가 바이트 일치
- 깨끗한 Rev 1 원본에 정방향 패치를 적용하면 exact O46과 일치
- 내부 검증용 역방향 복원은 깨끗한 원본과 일치
- 허용 범위 밖 변경 0바이트
- 수정 Mode2/Form1 섹터 EDC/P/Q ECC 정상
- 집중 PS1 런타임과 사용자 판정 통과

배포에는 정방향 xdelta와 적용·검증 도구, 문서, 라이선스 고지만
포함합니다. 원본·완성 BIN/CUE, 내부 역패치, 저장 데이터와 작업 자료는
포함하지 않습니다.
